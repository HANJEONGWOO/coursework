SLIDE 02 / 19 — LLM Serving at Scale
권장 35초 | 누적 00:30–01:05
설명 순서: 왼쪽: 동시 요청 → 오른쪽: 긴 문맥

[ENGLISH SCRIPT]
Large-scale LLM serving has two growing demands. First, a service must handle many user requests, so it batches requests to improve throughput. Second, each request may contain a long context, such as retrieved documents or a long reasoning history. Both demands increase the amount of information the model must retain. Oaken focuses on the memory pressure created when large batches and long contexts appear together.

[KOREAN TRANSLATION]
대규모 LLM 서빙에는 두 가지 요구가 커지고 있습니다. 첫째, 많은 사용자 요청을 처리해야 하므로 여러 요청을 배치로 묶어 처리량을 높입니다. 둘째, 검색된 문서나 긴 추론 이력처럼 개별 요청의 문맥도 길어지고 있습니다. 두 요구 모두 모델이 유지해야 할 정보의 양을 늘립니다. Oaken은 큰 배치와 긴 문맥이 동시에 나타날 때 발생하는 메모리 부담에 집중합니다.

[발표자 메모 · 낭독하지 않음]
그림의 '+10,000'은 서비스 요청 규모를 나타내는 예시입니다. 뒤의 평가에서 사용한 배치 크기 16~256과 구분합니다.

SLIDE 03 / 19 — Larger Batch and Longer Context: Capacity and Bandwidth
권장 30초 | 누적 01:05–01:35
설명 순서: 중앙의 핵심 문장만 강조

[ENGLISH SCRIPT]
The KV cache stores keys and values from previous tokens so that the model can reuse them during generation. Its size grows roughly with both batch size and context length. A larger cache needs more memory capacity, and reading that cache for each new token needs more bandwidth. Therefore, the same data structure creates two bottlenecks: how much we can store, and how quickly we can read it.

[KOREAN TRANSLATION]
KV 캐시는 이전 토큰의 키와 값을 저장해, 다음 토큰을 생성할 때 다시 사용할 수 있게 합니다. 그 크기는 대체로 배치 크기와 문맥 길이에 비례해 증가합니다. 캐시가 커지면 더 많은 메모리 용량이 필요하고, 새 토큰마다 그 캐시를 읽으려면 더 높은 대역폭도 필요합니다. 결국 하나의 자료구조가 얼마나 많이 저장할 수 있는지와 얼마나 빨리 읽을 수 있는지라는 두 가지 병목을 만듭니다.

[발표자 메모 · 낭독하지 않음]
원본 PDF에서는 파란 강조 화면이 배경 그림과 그래프를 가립니다. 화면에 보이지 않는 그래프를 가리키지 않도록 대본을 작성했습니다.

SLIDE 04 / 19 — KV Cache Matters for Bandwidth
권장 50초 | 누적 01:35–02:25
설명 순서: 그래프의 attention 20% → 22%, 오른쪽 공유 여부

[ENGLISH SCRIPT]
This slide explains why batching does not solve every utilization problem. In weight-based operations, several requests can reuse the same model weights, so batching improves compute utilization. Attention is different: each request has its own keys and values. These cannot generally be reused across unrelated requests. In the example, attention utilization changes only from about twenty to twenty-two percent, even though other operations improve substantially. The accelerator spends much of its time waiting for KV data, which makes attention a bandwidth bottleneck.

[KOREAN TRANSLATION]
이 슬라이드는 배치 처리가 모든 연산의 활용률 문제를 해결하지는 못하는 이유를 보여줍니다. 가중치를 사용하는 연산에서는 여러 요청이 같은 모델 가중치를 재사용할 수 있어, 배치 처리로 연산 자원의 활용률이 높아집니다. 하지만 attention에서는 요청마다 고유한 키와 값을 사용합니다. 서로 무관한 요청 사이에서는 이 데이터를 일반적으로 재사용할 수 없습니다. 여기서는 다른 연산의 활용률이 크게 개선되는 동안, attention의 활용률은 약 20퍼센트에서 22퍼센트로만 증가합니다. 가속기가 KV 데이터를 기다리는 시간이 길어지면서 attention이 대역폭 병목이 됩니다.

[발표자 메모 · 낭독하지 않음]
수치는 슬라이드에 제시된 A100·Llama2-13B·문맥 1K 조건의 예시입니다. '배치 attention 계산 자체가 불가능하다'는 의미가 아니라, 요청 간 KV 재사용의 이점이 제한된다는 뜻입니다.

SLIDE 05 / 19 — KV Cache Quantization as the Starting Point
권장 20초 | 누적 02:25–02:45
설명 순서: 중앙 강조 문구 → 다음 문제 제기

[ENGLISH SCRIPT]
A natural solution is to quantize the KV cache. Fewer bits per value reduce both storage and memory traffic. However, compression also introduces work: identifying unusual values, computing scales, and reconstructing data. The important question is whether the memory savings are large enough to outweigh these additional costs.

[KOREAN TRANSLATION]
자연스러운 해결책은 KV 캐시를 양자화하는 것입니다. 값 하나에 사용하는 비트 수를 줄이면 저장 공간과 메모리 전송량을 함께 줄일 수 있습니다. 하지만 압축에는 특이한 값을 식별하고, 스케일을 계산하고, 데이터를 복원하는 추가 작업도 필요합니다. 중요한 질문은 메모리에서 얻은 이득이 이러한 추가 비용을 넘어설 수 있는가입니다.

[발표자 메모 · 낭독하지 않음]
4장과 같은 배경을 사용하는 전환 슬라이드이므로 앞의 그래프 설명을 반복하지 않습니다.

SLIDE 06 / 19 — Why Algorithm–Hardware Co-design?
권장 40초 | 누적 02:45–03:25
설명 순서: 정확도와 실행 비용의 절충 → 공동 설계

[ENGLISH SCRIPT]
Existing approaches make different trade-offs. Fine-grained methods can preserve accuracy by handling outliers separately, but online profiling and mixed-precision processing add overhead. Coarser grouping or transformations can simplify execution, but may miss exceptions in the data distribution. Oaken's answer is to design the quantization algorithm and its hardware together. The goal is to keep useful precision while making grouping, storage, and reconstruction inexpensive enough to improve end-to-end performance.

[KOREAN TRANSLATION]
기존 방법들은 서로 다른 절충을 선택합니다. 세밀한 양자화 방법은 이상치를 별도로 처리해 정확도를 유지할 수 있지만, 실행 중 프로파일링과 혼합 정밀도 처리 비용이 추가됩니다. 더 큰 단위로 묶거나 변환을 적용하면 실행을 단순화할 수 있지만, 데이터 분포의 예외를 충분히 반영하지 못할 수 있습니다. Oaken은 양자화 알고리즘과 하드웨어를 함께 설계하는 방법을 제안합니다. 필요한 정밀도는 유지하면서 그룹 분류, 저장, 복원 비용을 줄여 전체 실행 성능을 높이는 것이 목표입니다.

[발표자 메모 · 낭독하지 않음]
원본의 비교 도표는 파란 강조 화면 아래에 가려져 있습니다. 개별 선행연구의 도표 위치를 가리키지 않고 핵심 절충만 설명합니다.

SLIDE 07 / 19 — Overview of Oaken
권장 30초 | 누적 03:25–03:55
설명 순서: 아래 왼쪽 알고리즘 3개 → 오른쪽 하드웨어

[ENGLISH SCRIPT]
Oaken has two connected parts. The algorithm uses offline thresholds for grouping, shifts value ranges before quantization, and combines dense and sparse storage. The hardware provides dedicated quantization and dequantization engines, together with page-based memory management. These components support one objective: reduce KV traffic while keeping the cost of processing the compressed representation low. I will first explain the algorithm, then show where the hardware fits.

[KOREAN TRANSLATION]
Oaken은 서로 연결된 두 부분으로 구성됩니다. 알고리즘은 사전에 정한 임계값으로 그룹을 나누고, 값의 범위를 이동시킨 뒤 양자화하며, dense와 sparse 저장을 결합합니다. 하드웨어는 전용 양자화·역양자화 엔진과 페이지 기반 메모리 관리를 제공합니다. 이 구성요소들은 KV 전송량을 줄이면서 압축된 표현을 처리하는 비용도 낮춘다는 하나의 목표를 지원합니다. 먼저 알고리즘을 설명하고, 이어서 하드웨어가 어디에 들어가는지 살펴보겠습니다.

[발표자 메모 · 낭독하지 않음]
dense는 모든 위치를 가지는 조밀 배열, sparse는 일부 위치와 그 부가정보만 저장하는 희소 배열이라는 뜻으로 사용합니다.

SLIDE 08 / 19 — Key Observations on KV Distribution
권장 50초 | 누적 03:55–04:45
설명 순서: 위에서 아래로 관찰 세 가지

[ENGLISH SCRIPT]
Three observations motivate the design. First, KV distributions differ across models and decoder layers, so calibration must reflect those differences. Second, the authors observe similar distributions across the tested input datasets. This suggests that grouping thresholds can be prepared offline and reused. Third, channel-wise patterns have exceptions, so grouping only by channel can lose accuracy. Oaken therefore groups values by magnitude. One distinction matters here: offline calibration provides the thresholds, while the actual group scales are still calculated online for each new token.

[KOREAN TRANSLATION]
설계의 출발점은 세 가지 관찰입니다. 첫째, KV 분포는 모델과 디코더 레이어에 따라 달라지므로 이 차이를 반영해 보정해야 합니다. 둘째, 저자들이 실험한 입력 데이터셋 사이에서는 분포가 비슷하게 나타났습니다. 따라서 그룹을 나누는 임계값을 오프라인에서 준비해 재사용할 수 있습니다. 셋째, 채널별 분포 패턴에도 예외가 있기 때문에 채널만을 기준으로 묶으면 정확도가 떨어질 수 있습니다. 그래서 Oaken은 값의 크기를 기준으로 그룹을 나눕니다. 여기서 구분할 점은 오프라인 보정으로 임계값을 정하되, 실제 그룹별 스케일은 새로운 토큰마다 온라인으로 계산한다는 것입니다.

[발표자 메모 · 낭독하지 않음]
슬라이드의 'shared quantization scale'을 실행 중 스케일까지 상수로 고정한다는 뜻으로 설명하지 않습니다. 논문 §4.3에서는 그룹별 min/max와 스케일을 온라인에서 계산합니다. 분포 유사성도 실험에서 관찰한 결과입니다.

SLIDE 09 / 19 — Threshold-based Online–Offline Quantization
권장 55초 | 누적 04:45–05:40
설명 순서: 왼쪽 topK·평균 → 가운데 임계값 → 오른쪽 새 토큰

[ENGLISH SCRIPT]
The offline stage runs sample inputs and collects four thresholds for each layer. Expensive top-K operations happen during this preparation, and the results are averaged. The paper reports roughly one hundred inference runs and about ten minutes for profiling. At runtime, each newly generated KV vector is classified using comparisons with those thresholds. Oaken then finds the minimum and maximum within each group and computes its quantization scale. This division moves costly threshold discovery out of the serving path while retaining adaptation to the current token's values.

[KOREAN TRANSLATION]
오프라인 단계에서는 예제 입력을 실행하고 레이어마다 네 개의 임계값을 수집합니다. 비용이 큰 top-K 연산은 이 준비 단계에서 수행하며, 얻은 결과의 평균을 사용합니다. 논문은 프로파일링에 약 100회의 추론과 약 10분이 필요하다고 보고합니다. 실행 중에는 새로 생성된 KV 벡터의 값을 이 임계값들과 비교해 분류합니다. 이후 그룹마다 최솟값과 최댓값을 구하고 양자화 스케일을 계산합니다. 이렇게 역할을 나누면 비용이 큰 임계값 탐색을 서빙 경로 밖으로 옮기면서도, 현재 토큰의 값에 맞추어 양자화할 수 있습니다.

[발표자 메모 · 낭독하지 않음]
약 10분은 저자의 측정 조건에서 보고한 준비 비용이며 모든 장비의 보장값이 아닙니다. 양자화 범위는 새 토큰의 KV 벡터이며, 과거 캐시 전체를 매번 재양자화한다고 설명하지 않습니다.

SLIDE 10 / 19 — Three Groups and the Cost of Outliers
권장 45초 | 누적 05:40–06:25
설명 순서: middle / inner / outer → 오른쪽 23-bit 항목

[ENGLISH SCRIPT]
The four thresholds define three groups. Most values belong to the middle group and use the dense inlier representation. The outer group contains very large magnitudes, while the inner group contains very small magnitudes that could otherwise disappear during quantization. Both are handled as outliers. A straightforward design stores these outliers in FP16 with an index and a group identifier. Here, that requires twenty-three bits per sparse entry. So separating outliers helps accuracy, but creates a storage and hardware problem of its own.

[KOREAN TRANSLATION]
네 개의 임계값은 세 그룹을 정의합니다. 대부분의 값은 middle 그룹에 속하며 dense inlier 표현을 사용합니다. outer 그룹에는 크기가 매우 큰 값이, inner 그룹에는 양자화 과정에서 사라질 수 있는 매우 작은 값이 들어갑니다. 이 두 그룹을 모두 outlier로 처리합니다. 단순한 설계에서는 outlier를 FP16으로 저장하고 위치 인덱스와 그룹 식별자를 붙입니다. 여기서는 sparse 항목 하나에 23비트가 필요합니다. 따라서 outlier 분리는 정확도에 도움이 되지만, 별도의 저장 공간과 하드웨어 비용을 만듭니다.

[발표자 메모 · 낭독하지 않음]
23비트 = 위치 6 + 그룹 1 + 값 16입니다. Oaken의 inlier는 중앙의 inner 그룹이 아니라 middle 그룹입니다. 매우 작은 값도 outlier로 별도 취급한다는 점을 강조합니다.

SLIDE 11 / 19 — Group Shift Quantization
권장 55초 | 누적 06:25–07:20
설명 순서: 분포를 0 근처로 이동 → INT4 / INT5

[ENGLISH SCRIPT]
Group shift reduces the range that the quantizer needs to cover. For a large positive value, Oaken subtracts the positive outer threshold; for a large negative value, it subtracts the negative threshold. Both tails move closer to zero, reducing the unused gap between them. A similar shift applies to the middle group, while the inner group stays unchanged. Oaken then uses four bits for middle-group values and five bits for outliers. With the existing index and group fields, a sparse entry shrinks from twenty-three to twelve bits. Here, shift means translating a numerical range by subtraction.

[KOREAN TRANSLATION]
Group shift는 양자화기가 표현해야 하는 범위를 줄입니다. 큰 양수에서는 양의 outer 임계값을 빼고, 큰 음수에서는 음의 임계값을 뺍니다. 그러면 양쪽 꼬리 분포가 0에 가까워지고, 그 사이에서 사용되지 않는 간격이 줄어듭니다. middle 그룹에도 비슷한 이동을 적용하고, inner 그룹은 그대로 둡니다. 이후 middle 그룹 값은 4비트, outlier는 5비트로 양자화합니다. 기존 위치 인덱스와 그룹 필드를 포함하면 sparse 항목의 크기는 23비트에서 12비트로 줄어듭니다. 여기서 shift는 뺄셈으로 수치 범위를 평행 이동한다는 뜻입니다.

[발표자 메모 · 낭독하지 않음]
비트 시프트 연산과 구분합니다. 예를 들어 양의 임계값이 10일 때 값 12는 이동 후 2가 됩니다. 12비트 항목은 위치 6 + 그룹 1 + 양자화 값 5입니다. 슬라이드의 평균 5.9→4.8은 원문 표기이며 전체 저장 비트 계산은 다음 장 메모를 참고합니다.

SLIDE 12 / 19 — Fused Dense-and-Sparse Encoding
권장 50초 | 누적 07:20–08:10
설명 순서: dense의 빈 4비트 칸 → sparse의 8비트 부가정보

[ENGLISH SCRIPT]
The next idea uses space that would otherwise be wasted. After outliers are separated, their positions in the dense array contain zeros. Oaken places four bits of each quantized outlier in those existing positions. The sparse array then stores only the six-bit index, one group bit, and one sign bit. This reduces the separate sparse entry to eight bits, which is convenient for memory alignment. The structural benefit is clear: reuse the dense slot and keep sparse metadata compact. For overall storage, the paper's evaluation reports effective bitwidths of roughly four point eight bits per value.

[KOREAN TRANSLATION]
다음 아이디어는 원래 낭비될 공간을 활용하는 것입니다. outlier를 분리하면 dense 배열에서 해당 위치는 0으로 채워집니다. Oaken은 양자화한 outlier의 4비트를 이 기존 위치에 넣습니다. 그러면 sparse 배열에는 6비트 인덱스, 그룹 비트 하나, 부호 비트 하나만 남습니다. 별도의 sparse 항목이 8비트가 되어 메모리 정렬에 유리해집니다. 핵심 이점은 dense의 기존 칸을 재사용하고 sparse 부가정보를 작게 유지한다는 것입니다. 전체 저장 비용은 논문의 평가에서 값 하나당 약 4.8비트의 유효 비트 수로 보고됩니다.

[발표자 메모 · 낭독하지 않음]
원본 슬라이드에는 평균 4.8→4.4라고 쓰여 있지만, dense 4비트/위치와 outlier 10%의 추가 8비트를 모두 세면 4 + 0.1×8 = 4.8비트입니다(스케일 등 제외). 논문 Table 2는 4.82~4.89를 보고합니다. 4.4를 실제 전체 저장 비트 수로 단정하지 않도록 대본에서는 항목 구조와 논문 실측 유효 비트를 설명합니다.

SLIDE 14 / 19 — Oaken Hardware Modules
