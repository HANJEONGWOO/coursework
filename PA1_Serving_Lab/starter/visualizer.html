Model and replay conventions

For simulator runs, prefill costs N / prefill_rate; an iteration with decode adds decode_base + decode_per_request × decoding requests. Costs are added, with no overlap. A token budget is not a time budget. Prefill completion emits output 1. Later decode consumes the previous output. Admission reserves the entire prompt; useful KV content grows as input is processed. Final KV length before release is prompt + output − 1. No eviction or failed-request recovery is modeled. Queue recovery in the traffic study is a separate metric.

The memory grid shows the current iteration's reserved blocks after planning/growth, before completion releases. Useful positions describe processed input. Events show exact admission, growth, and release changes. SLO (Service Level Objective) summaries are final-run results, not predictions at the cursor. A single gap crossing a threshold is distinct from failing the request's P95 inter-token latency (ITL) criterion.

All assignment recordings use synthetic time units, not GPU measurements. Invalid or incomplete runs have no performance summary. The viewer does not execute or repair student policies.
